# SalonOne 連携ガイド

このダッシュボードは、売上管理ツール **SalonOne** の分析API（読み取り専用）からデータを取得して表示します。
売上・来店・マーケの手入力は不要です。SalonOneにない項目（次回予約数・ブログ/SNS更新・★5口コミなど）だけを
日報入力タブから手入力し、サーバー（Upstash）に保存して全端末で共有します。

## 仕組み

```
ブラウザ ──(セッションクッキー)──▶ Vercel サーバーレス関数 (/api/*) ──(APIキー)──▶ SalonOne 分析API
```

- SalonOneのAPIキーは**サーバー側の環境変数にのみ**保存され、ブラウザには一切渡りません。
- 権限（管理者 / 店舗 / スタッフ）はサーバー側で強制されます。スタッフ用URLのセッションでは、
  他店舗の`shop_id`を指定してもサーバーが自店舗に強制的に絞り込みます。
- 顧客データはサーバー側で個人情報項目を除去し、年代分布などの集計値のみをブラウザに返します。

## 環境変数（Vercelのプロジェクト設定で登録）

| 変数 | 必須 | 内容 |
|---|---|---|
| `SALONONE_API_KEY` | ◎ | SalonOneのブランド選択画面「API連携」で発行したアクセスキー。**未設定の場合はデモデータで動作**（ヘッダーに「デモデータ」表示） |
| `AUTH_SECRET` | 推奨 | セッション署名用のランダム文字列（例: `openssl rand -hex 32`）。未設定時はAPIキーから導出 |
| `ADMIN_PASSWORD` | 推奨 | オーナービュー（URLパラメータなし）のパスワード。未設定なら誰でもオーナービューを開けます（本番では設定推奨） |
| `MANAGER_PASSWORD` | 任意 | マネージャービュー（`?mode=manager`）のパスワード |
| `STORE_PASSWORDS` | 任意 | 店長ビュー（`?store=◯`）のパスワードのJSON。例: `{"chiba":"pass1","53":"pass2"}` キーはスラッグ/shop_id/店名のいずれでも可 |
| `STAFF_PASSWORDS` | 任意 | スタッフ専用URLのパスワードのJSON。例: `{"chiba_kiki":"pass1","101_1002":"pass2"}` キーは `店舗_スタッフ`（URLパラメータ表記 or ID）またはスタッフ名小文字。未設定のスタッフはパスワードなしで閲覧可 |
| `STORE_SLUGS` | 任意 | 旧URLの店舗スラッグ → SalonOne shop_id の対応。例: `{"chiba":101,"honatsugi":102,"yamato":103}` 未設定でも店名マッチ（chiba→「千葉」を含む店名）で自動解決を試みます |
| `GEMINI_API_KEY` | 任意 | 設定するとAIコーチ（スタッフ向けアドバイス生成）が有効になります |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | 推奨 | 日報（次回予約/ブログ/SNS/★5口コミ）・物販売上・広告費・入金突合・シフト・**月次目標・基本給**のサーバー保存先。VercelのプロジェクトでStorage → **Upstash for Redis** を追加すると自動設定されます。未設定でも動作しますが、入力データは各端末のブラウザにのみ保存されます |
| `GEMINI_MODEL` | 任意 | 既定: `gemini-2.0-flash` |
| `SALONONE_BASE_URL` | 任意 | 既定: `https://salonone.net/api/analytics/v1` |

> **APIキー発行時の注意**: 「個人情報を含めない」設定での発行を推奨します。ダッシュボードは
> 個人情報を使いません（含めるキーでもサーバー側で除去されます）。

## デプロイ（Vercel）

1. このリポジトリをVercelにインポート（Framework Preset: **Other**。ビルド設定は不要）
2. 環境変数を設定（上表）
3. デプロイ

静的ファイル（`index.html`, `assets/`）と `api/` 配下のサーバーレス関数が自動で配信されます。

## 権限とURL（4段階）

| 役割 | URL | パスワード環境変数 | 見えるもの |
|---|---|---|---|
| オーナー | `/` | `ADMIN_PASSWORD` | 全店舗・全機能（給与インセンティブ・設定を含む） |
| マネージャー | `/?mode=manager` | `MANAGER_PASSWORD` | 全店舗の分析一式（サマリー/売上/マーケ/顧客/目標/日報入力/広告費入力）。**給与と設定は不可** |
| 店長 | `/?store=<店舗>` | `STORE_PASSWORDS`（JSON。キーはスラッグ/ID/店名） | 自店舗の分析一式（マーケ・目標設定・自店スタッフの日報/物販入力を含む）。給与・設定・広告費は不可 |
| スタッフ | `/?store=<店舗>&staff=<スタッフ>` | `STAFF_PASSWORDS`（JSON） | マイダッシュボード・売上詳細・カレンダー・自分の日報入力（自店舗のみ） |

- `<店舗>` / `<スタッフ>` は 旧スラッグ（chiba等）・SalonOneのID・名前 のいずれでも指定できます
- 各URLは 設定タブ → 「共有URLの発行」から生成できます
- **スタッフ・店長のパスワードは設定タブ「スタッフアカウントの発行」から画面上で設定できます**
  （scryptハッシュでサーバー保存・Upstash連携が必要。環境変数より優先されます）
- スタッフはヘッダーの切替で「自分の成績 / 店舗全体」を行き来できます（マイダッシュボードは常に本人）
- 上位の役割でログイン済みなら、下位のURLを開いても再ログインは不要です
  （例: 店長は自店スタッフの専用URLをそのまま閲覧可）
- パスワード未設定の役割はURLを知っていれば誰でも開けます（設定タブの連携状態に警告表示）。
  **本番運用では最低限 `ADMIN_PASSWORD` の設定を推奨します**
- 制限はタブの表示だけでなくサーバー側でも強制されます
  （店長/スタッフのセッションは他店舗の`shop_id`を指定しても自店舗に固定、
  スタッフには広告指標・顧客集計をAPIレベルで返しません）

## 売上の基準（重要）

実APIを検証した結果、**日別・スタッフ別・支払い内訳は「会計済み売上（digest_sales）」基準で整合**しており、
粗売上（gross_sales）は月合計にしか存在しません（回数券等の購入時計上分を含むため日別合計より大きい）。
画面内で数字がズレないよう、ダッシュボードは**既定で会計済み売上に統一**しています。
設定タブ「売上の基準」で 粗売上 / 消化売上 に切り替えられます（端末ごとの表示設定）。

また「新規」は2種類あります: 売上サマリの **新規来店（延べ）** と、マーケ集計の **新規客（初めて予約した人数・1人=1）**。
定義が違うため一致しません（画面ラベルに明記）。

## データの定義（SalonOne API仕様より）

- **粗売上** = 購入時点で計上。回数券・サブスクは購入時に全額計上
- **消化売上** = 施術提供時点で計上（失効益を含む）
- **会計済み売上** = 会計が完了した売上
- 売上・マーケの数値はSalonOne管理画面の「売上分析」「マーケティング分析」と同じ計算です
- 入会率は**予約数ベース**（`join_rate_by_booking`）を表示しています。来店数ベースの入会率は
  100%を超えることがあるため使用していません
- 月次推移で使う入会数は**期間内に契約した人数**（`join_in_period_count`）です。
  「今までに契約したか」で数える`join_count`は過去月の数値が後から増えるため使用していません

## 手入力データ（APIにない項目）

SalonOne APIから取得できない以下の項目は、**日報入力タブ**から手入力します:

| 項目 | 粒度 | 入力できる人 | 反映先 |
|---|---|---|---|
| **新規の次回予約数・既存の次回予約数** | 日次×スタッフ | スタッフ本人・店長・管理者 | 日報サマリ・マイダッシュボードの次回予約率（分母はSalonOneの同月来店数） |
| ブログ更新数・SNS更新数・★5口コミ数 | 日次×スタッフ | スタッフ本人・店長・管理者 | サマリーの「日報サマリ」（目標: ブログ10件/月） |
| 物販売上（税込） | 月次×スタッフ | 店長・管理者 | インセンティブ計算（APIの`product_sales`が0または無い場合のフォールバック） |
| 広告費 | 月次×媒体 | オーナー・マネージャー | マーケティングのCPA・ROAS（HPB掲載料などAPIに広告費がない媒体用） |

日報入力タブの使い方:
- 日付は「前日/翌日/今日」ボタンかカレンダー入力で移動。未来日は選べません
- 「この月の入力状況」に入力済みの日が ✓ で表示され、タップでその日に移動できます
- 各項目は −/＋ ボタンか直接入力。保存すると右上に「✓ 保存済み 20:10」と表示されます（未保存の変更がある間は黄色の表示）
- 店長・管理者は「本日の日報」の未入力スタッフが一覧され、名前をタップするとそのスタッフの入力に切り替わります
- 保存はサーバー側でキー単位のロックを取るため、複数スタッフが同時に保存しても消えません

## 月次目標・基本給（サーバー保存）

売上目標設定タブの目標（売上・新規来店・入会数）とインセンティブタブの基本給は `/api/goals` 経由で
Upstashに保存され、**全端末・スタッフのマイダッシュボード（目標リング・進捗）に反映**されます。

- 権限: オーナー/マネージャー = 全店舗、店長 = 自店舗と所属スタッフ、スタッフ = 閲覧のみ（自分と自店舗）。基本給はオーナーのみ
- 旧バージョンで端末に保存されていた目標は、サーバーが空のとき初回起動時に自動で引き継がれます
- エクスポート/インポートはバックアップ用途として残しています（インポートはサーバーに保存されます）

> 実APIは仕様書に記載のない拡張フィールド（物販売上・稼働率・支払い方法内訳・Google/HPB口コミ数など）を
> 返すことが確認されており、ダッシュボードはこれらを自動で活用します（支払い内訳バー・稼働率カード等）。

## 入金突合（オーナー/マネージャー/店長）

「入金突合」タブで、SalonOneの支払い方法別の記録額（`payment_breakdown`）と実際の入金を照合できます。

- **日次**: 現金はレジ実査額、カード/QRは決済端末の当日集計額を入力 → 差額を自動計算・メモ付き
- **月間**: 日別の突合状況一覧（✅一致 / ⚠差異 / 未入力）と支払い方法別の月間集計
  （月末にカード会社・QR事業者の入金明細と照合する際に使用）
- カード/QRの銀行入金は後日のため、**日次照合は端末集計ベース**を推奨しています

## シフト希望休の申請・承認（全役割）

「シフト」タブで希望休の申請〜自動分配〜承認ができます（サーバー保存 = Upstash 必須）。

- **ルール（既定）**: 月8日休み・うち土日の休みは1日・自動割当は同日2人まで
  → 設定タブ「シフトルール」から変更できます
- **スタッフ**: 来月のカレンダーで希望日をタップ → 申請（ルールの枠はUIで制御）
- **店長/マネージャー/オーナー**: 「自動分配」で希望日を尊重しつつ、
  土日枠の超過調整・不足分の平日割当（休みが同日に集中しないよう分散）を実行 →
  必要なら手調整 → 承認。承認結果はスタッフの画面に表示されます

保存先はVercelの **Upstash for Redis** 連携（無料枠あり）:
1. Vercelのプロジェクト → Storage タブ → Upstash for Redis を追加
2. 環境変数（`KV_REST_API_URL` / `KV_REST_API_TOKEN`）が自動設定される → 再デプロイ

未設定の場合も入力タブは使えますが、データは**入力した端末のブラウザにのみ**保存されます
（画面に注意書きが表示されます）。

## 既知の前提・確認事項

- **マーケ集計のshop_id**: 仕様書ではマーケ集計（§6）のパラメータに`shop_id`が明記されていません。
  本ダッシュボードは`shop_id`での店舗絞り込みを送信します。実APIが受け付けない場合、
  店舗フィルタ選択時のマーケ数値がブランド全体になる、または`invalid_request`になる可能性があるため、
  導入時にSalonOne運営へ対応状況をご確認ください（防御として、ロック済みセッションの担当者別集計は
  サーバー側で自店舗スタッフの行のみに絞り込んでいます）。
- **リテンションのフィールド名**: 仕様書§6は項目名を明記していないため、想定される複数の名前に
  耐性を持たせています。実レスポンスと合わない場合はブラウザのコンソールに警告が出ます。

## ローカル開発

```bash
npm install
node scripts/dev-server.mjs 3000
# → http://localhost:3000 （SALONONE_API_KEY未設定ならデモデータ）
```

CSSを変更した場合は `npm run build:css` でTailwindを再生成してください。

## 旧バージョンからの変更点

- **削除**: カウンセリング回答表示（専用タブ・マーケタブ内の管理者用ブラウザ）、データ編集タブ、
  月締め確定、GAS/スプレッドシート連携（売上・来店・マーケの手入力はSalonOne自動取得に置き換え）
- **追加**: 継続顧客（リテンション）分析、年代分布、媒体別CPA/ROAS表示、CSVエクスポート、
  曜日別分析、キャンセル率KPI
- **セキュリティ改善**: APIキー・Geminiキーのサーバー側移行、HMAC署名付きセッション、
  サーバー側での店舗スコープ強制、個人情報のサーバー側除去、XSS対策（エスケープ処理）
- **目標・基本給**: スプレッドシート同期は廃止し、サーバー（Upstash）保存になりました。
  Upstash未設定の環境ではブラウザ（localStorage）保存にフォールバックし、エクスポート/インポートで持ち運べます
- **日報入力（復活・刷新）**: FAB/モーダル方式は廃止し、日報入力タブ（ステッパー・入力状況カレンダー・保存状態表示）に統合
