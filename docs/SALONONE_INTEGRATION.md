# SalonOne 連携ガイド

このダッシュボードは、売上管理ツール **SalonOne** の分析API（読み取り専用）からデータを取得して表示します。
スタッフによる売上の手入力は不要になり、閲覧・分析専用のツールです。

## 仕組み

```
ブラウザ ──(セッションクッキー)──▶ Vercel サーバーレス関数 (/api/*) ──(APIキー)──▶ SalonOne 分析API
```

- SalonOneのAPIキーは**サーバー側の環境変数にのみ**保存され、ブラウザには一切渡りません。
- 権限（管理者 / 店舗 / スタッフ）はサーバー側で強制されます。スタッフ用URLのセッションでは、
  他店舗の`shop_id`を指定してもサーバーが自店舗に強制的に絞り込みます。
- 顧客データはサーバー側で個人情報項目を除去し、年代分布などの集計値のみをブラウザに返します。

## 環境変数（Vercelのプロジェクト設定で登録）

| 変数 | 必須 | 内容 |
|---|---|---|
| `SALONONE_API_KEY` | ◎ | SalonOneのブランド選択画面「API連携」で発行したアクセスキー。**未設定の場合はデモデータで動作**（ヘッダーに「デモデータ」表示） |
| `AUTH_SECRET` | 推奨 | セッション署名用のランダム文字列（例: `openssl rand -hex 32`）。未設定時はAPIキーから導出 |
| `ADMIN_PASSWORD` | 任意 | 管理者ビュー（URLパラメータなし）のパスワード。未設定なら誰でも管理者ビューを開けます（旧ツールと同じ挙動） |
| `STAFF_PASSWORDS` | 任意 | スタッフ専用URLのパスワードのJSON。例: `{"chiba_kiki":"pass1","101_1002":"pass2"}` キーは `店舗_スタッフ`（URLパラメータ表記 or ID）またはスタッフ名小文字。未設定のスタッフはパスワードなしで閲覧可 |
| `STORE_SLUGS` | 任意 | 旧URLの店舗スラッグ → SalonOne shop_id の対応。例: `{"chiba":101,"honatsugi":102,"yamato":103}` 未設定でも店名マッチ（chiba→「千葉」を含む店名）で自動解決を試みます |
| `GEMINI_API_KEY` | 任意 | 設定するとAIコーチ（スタッフ向けアドバイス生成）が有効になります |
| `GEMINI_MODEL` | 任意 | 既定: `gemini-2.0-flash` |
| `SALONONE_BASE_URL` | 任意 | 既定: `https://salonone.net/api/analytics/v1` |

> **APIキー発行時の注意**: 「個人情報を含めない」設定での発行を推奨します。ダッシュボードは
> 個人情報を使いません（含めるキーでもサーバー側で除去されます）。

## デプロイ（Vercel）

1. このリポジトリをVercelにインポート（Framework Preset: **Other**。ビルド設定は不要）
2. 環境変数を設定（上表）
3. デプロイ

静的ファイル（`index.html`, `assets/`）と `api/` 配下のサーバーレス関数が自動で配信されます。

## 権限とURL

旧ツールの権限モデルをそのまま踏襲しています:

| ビュー | URL | 見えるもの |
|---|---|---|
| 管理者 | `/` | 全店舗・全機能（マーケ・インセンティブ・目標設定・設定を含む） |
| 店舗 | `/?store=<店舗>` | その店舗のサマリー・売上・顧客分析・カレンダー |
| スタッフ | `/?store=<店舗>&staff=<スタッフ>` | マイダッシュボード・売上詳細・カレンダー（自店舗のみ） |

`<店舗>` / `<スタッフ>` は 旧スラッグ（chiba等）・SalonOneのID・名前 のいずれでも指定できます。
スタッフ用URLは 設定タブ → 「スタッフ専用URLの発行」から生成できます。

## データの定義（SalonOne API仕様より）

- **粗売上** = 購入時点で計上。回数券・サブスクは購入時に全額計上
- **消化売上** = 施術提供時点で計上（失効益を含む）
- **会計済み売上** = 会計が完了した売上
- 売上・マーケの数値はSalonOne管理画面の「売上分析」「マーケティング分析」と同じ計算です
- 入会率は**予約数ベース**（`join_rate_by_booking`）を表示しています。来店数ベースの入会率は
  100%を超えることがあるため使用していません
- 月次推移で使う入会数は**期間内に契約した人数**（`join_in_period_count`）です。
  「今までに契約したか」で数える`join_count`は過去月の数値が後から増えるため使用していません

## 既知の前提・確認事項

- **マーケ集計のshop_id**: 仕様書ではマーケ集計（§6）のパラメータに`shop_id`が明記されていません。
  本ダッシュボードは`shop_id`での店舗絞り込みを送信します。実APIが受け付けない場合、
  店舗フィルタ選択時のマーケ数値がブランド全体になる、または`invalid_request`になる可能性があるため、
  導入時にSalonOne運営へ対応状況をご確認ください（防御として、ロック済みセッションの担当者別集計は
  サーバー側で自店舗スタッフの行のみに絞り込んでいます）。
- **リテンションのフィールド名**: 仕様書§6は項目名を明記していないため、想定される複数の名前に
  耐性を持たせています。実レスポンスと合わない場合はブラウザのコンソールに警告が出ます。

## ローカル開発

```bash
npm install
node scripts/dev-server.mjs 3000
# → http://localhost:3000 （SALONONE_API_KEY未設定ならデモデータ）
```

CSSを変更した場合は `npm run build:css` でTailwindを再生成してください。

## 旧バージョンからの変更点

- **削除**: カウンセリング回答表示（専用タブ・マーケタブ内の管理者用ブラウザ）、データ編集タブ、
  日報入力（FAB・モーダル）、広告費の手入力（APIの`ad_spend`/`cpa`/`roas`で代替）、
  ブログ/SNS進捗（手入力データが源泉のため）、月締め確定、GAS/スプレッドシート連携
- **追加**: 継続顧客（リテンション）分析、年代分布、媒体別CPA/ROAS表示、CSVエクスポート、
  曜日別分析、キャンセル率KPI
- **セキュリティ改善**: APIキー・Geminiキーのサーバー側移行、HMAC署名付きセッション、
  サーバー側での店舗スコープ強制、個人情報のサーバー側除去、XSS対策（エスケープ処理）
- **目標・基本給**: スプレッドシート同期は廃止し、ブラウザ（localStorage）保存になりました。
  端末間で共有する場合は目標設定タブのエクスポート/インポートを使用してください
