# 給与・インセンティブ（2026年11月分〜）

アイラッシュサロン（本厚木店・千葉店）の社員の月次給与を、ダッシュボードの **インセンティブ** タブで計算します。
対象は **2026年11月分から** です。**2026年10月分まで** の月を選ぶと、これまでの計算（施術40% − 基本給・物販10%）の表がそのまま出ます。

## 計算のしかた

| 項目 | 計算 |
|---|---|
| 基本給・固定残業代 | 給与パターンで決まる（下の表） |
| 税込施術売上 | SalonOne の **会計済み売上（税込）** − 物販売上。担当は SalonOne の会計担当スタッフ。担当者なしの売上は誰にも入らない |
| 到達した率 | 税込施術売上が各段階の金額を **超えたら** その率（ちょうど同額は前の段階のまま） |
| インセンティブ | （税込施術売上 − 開始ライン）× 到達した率。開始ライン以下は0円。1円未満切り上げ |
| 開店・締め作業 | パターンの標準と違うときだけ率を調整（時短が担う → 全段階+1%、フルが担わない → 全段階−1%） |
| 次の段階 | 次の段階の金額・率・あと何円か（ちょうど同額のときは「あと1円」）。最上位なら「次の段階なし」 |
| 物販手当 | 税込物販売上 × 5%。**10万円を超えたら全額に10%**。1円未満切り上げ。開店・締めの調整なし |
| 残業の追加支給 | 基本給部分（基本給 ÷ 月平均所定 × 1.25 × 残業時間）＋ インセンティブ部分（インセンティブ ÷ 総労働時間 × 0.25 × 法定時間外の時間）− 固定残業代。マイナスは0円、1円未満切り上げ。物販手当はインセンティブ部分に含めない |
| 総支給 | 基本給 ＋ 固定残業代 ＋ インセンティブ ＋ 物販手当 ＋ 残業の追加支給 |

- 物販売上は SalonOne の物販売上を使い、0 または無い場合は日報入力タブの「物販売上（月次・税込）」の手入力値を使います
- 返金は SalonOne で管理します（SalonOne の会計済み売上をそのまま使い、返金があった月は画面に注意を出します）
- 締め日は月末（1日〜末日）です
- 法定休日と深夜の割増は対象外です

### 給与パターン（2026年11月〜の金額）

| キー | 名称 | 勤務時間（休憩45分） | 月平均所定 | 基本給 | 固定残業 | 開店・締め（標準） | 段階（税込施術売上を超えたら → 率） |
|---|---|---|---|---|---|---|---|
| full | フル | シフト制・実働8h | 179.33h | 230,300 | 6h・9,700 | 担う | 606,000→38% / 900,000→39% / 950,000→40% / 1,000,000→41% / 1,050,000→42% |
| short_atsugi | 時短・本厚木 | 10:00〜17:45・実働7h | 156.92h | 212,600 | 3h・5,100 | 担わない | 532,000→36% / 559,000→37% / 760,000→38% / 830,000→39% / 870,000→40% |
| short_chiba | 時短・千葉 | 10:00〜17:30・実働6h45m | 151.31h | 205,000 | 3h・5,100 | 担わない | 513,000→36% / 539,000→37% / 760,000→38% / 830,000→39% / 870,000→40% |

月平均所定 ＝ 年間出勤日数269日 × 1日の実働 ÷ 12（小数第2位まで）。

## 画面での使い方（オーナー）

1. 期間を「今月」にし、対象月（例: 2026年11月）を選んで **インセンティブ** タブを開く
2. 「給与パターン未設定のスタッフ」から、社員の **給与パターン** を選ぶ（パート・業務委託の方は未設定のまま）
3. 標準と違う人だけ **開店・締め作業** を切り替える
4. 月が終わったら、勤怠から **残業時間・法定時間外・総労働時間** を入力して「勤怠を保存」
   - 未入力の月は、残業の追加支給を0円として総支給を出します（カードに「残業精算前」と表示）
5. 総支給・インセンティブ・物販手当の合計は画面上部に出ます

給与パターンと開店・締めは **「この月から」の設定** として保存されます。
たとえば 2027年2月を開いてパターンを変えると、2027年2月以降だけが変わり、2026年11月〜2027年1月は当時の設定のまま計算されます。
「未設定（対象外）」を選ぶと、その月から計算の対象外になります（退職・パートへの変更など）。

## 誰が見られるか

| 役割 | できること |
|---|---|
| オーナー | 全員分の閲覧・設定・勤怠の入力 |
| スタッフ | **マイ成績** の「給与の見込み」で本人の分だけ見られる（入力はできない） |
| マネージャー・店長 | 見られない |

見られる範囲はサーバー側で制限しています（スタッフがほかの人の分を取得しようとしても返しません）。

## 保存先

Supabase の表 `vie_kv` に、次のキーで保存します（表の形は変えていません。SQLの実行は不要）。
給与に使う売上は、画面の店舗の絞り込みに関係なく、サーバーが SalonOne から **全店舗の合計** を取って計算します（2店舗で働く人の売上も漏れません。本人の画面とオーナーの画面で同じ金額になります）。

| キー | 中身 |
|---|---|
| `vie:payroll:staff` | スタッフごとの「◯月から」の給与パターン・開店締めの履歴 |
| `vie:payroll:hours:<YYYY-MM>` | その月の残業時間・法定時間外の時間・総労働時間 |

既存の基本給（`vie:salaries`）・日報や物販（`vie:manual:<YYYY-MM>`）には書き込みません。

## 金額を変えるとき（毎年10月の最低賃金改定など）

金額・率・時間はすべて **`assets/js/payroll/config.js`** の1か所にあります。
**今あるブロックは書き換えずに残し、新しいブロックを追加** してください。過去の月は当時の金額のまま計算されます。

1. `assets/js/payroll/config.js` を開く
2. `PAYROLL_RULES` の中の `from: '2026-11'` のブロックを丸ごとコピーして、そのすぐ下（`]` の前）に貼り付ける
3. 貼り付けた方の `from` を新しい適用開始月にする（例: `from: '2027-10'`）。`label` も `'2027年10月〜'` にする
4. 貼り付けた方の金額を新しい値に変える（基本給 `baseSalary`、固定残業代 `fixedOtPay`、固定残業時間 `fixedOtHours`、月平均所定 `monthlyScheduledHours`、段階 `tiers`、物販 `retailTiers` など）
   - パターンのキー（`full` / `short_atsugi` / `short_chiba`）は変えない（スタッフの設定と結びついています）
5. `tests/payroll.test.mjs` に新しい金額のテストを1つ足し、`npm test` がすべて成功することを確かめる
6. 画面で 2027年9月（古い金額）と 2027年10月（新しい金額）を開いて、基本給などが切り替わることを確かめる

例（2027年10月からフルの基本給を変える場合。数字は例です）:

```js
export const PAYROLL_RULES = [
    { from: '2026-11', label: '2026年11月〜', /* …今のまま… */ },
    {
        from: '2027-10', label: '2027年10月〜',
        /* salesField・storeDutyRateAdjust・overtime・retailTiers は上と同じ内容をコピー */
        patterns: {
            full: { /* …上のコピーで baseSalary などを新しい金額に… */ },
            short_atsugi: { /* … */ },
            short_chiba: { /* … */ },
        },
    },
];
```

## プログラムの構成（開発者向け）

| ファイル | 役割 |
|---|---|
| `assets/js/payroll/config.js` | 設定値（適用開始月つき）。`ruleForMonth('YYYY-MM')` でその月の設定を選ぶ（旧ルールの月は null） |
| `assets/js/payroll/calc.js` | 計算だけをする関数（画面・データベースと切り離し） |
| `assets/js/data/payroll.js` | 保存・読み込みと、SalonOne の売上からスタッフ1人分の計算をとりまとめる |
| `assets/js/views/payroll.js` | インセンティブタブの新しい画面（オーナー） |
| `assets/js/views/staff.js` | マイ成績の「給与の見込み」（本人） |
| `assets/js/views/incentive.js` | 対象月で新しい画面と従来の表を切り替える。2026年10月分までの計算（`renderLegacy`）は変更なし |
| `api/_lib/payroll.js` | 保存先のAPI（権限チェック・入力チェック・SalonOne から全店舗のスタッフ別売上を取得）。呼び出しは `/api/goals?kind=payroll&month=YYYY-MM`（Vercel の Hobby プランの関数12個の上限を超えないよう、`api/goals.js` から振り分け） |
| `tests/payroll.test.mjs` | 自動テスト（`npm test`） |
