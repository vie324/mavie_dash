# 業務分担ガイド（SalonOne × vie ダッシュボード）

**SalonOne は「記録する場所」、このダッシュボードは「見る・振り返る・決める場所」** です。
売上・来店・新規などの数字はすべて SalonOne の入力から自動で作られます。
このツールで手入力するのは **SalonOne にない数字だけ**（日報の次回予約・入金の実際額・目標など）です。
アイラッシュサロンなので回数券・サブスクの「入会」は指標にせず、**次回予約（新規 / 2回目以降）** と媒体別の次回予約で再来を見ます。

アプリ内でも「その他 → 使い方・業務分担」から同じ内容をスマホで確認できます。

| 広告費（Meta/TikTok） | ◎ | 確認 | SalonOneの広告連携の値を自動取得 |
| 広告費（HPBなどAPIに無い媒体） | — | ◎ | 日報入力タブの広告費欄（オーナー/マネージャー） |

## 3. 見る数字の定義と目安

| 指標 | 定義 | 目安・表示 | どこで見る |
|---|---|---|---|
| 売上（会計済み） | 会計が完了した売上。日別・スタッフ別・支払い内訳と一致する基準（設定で粗売上/消化売上に切替可） | 目標に対する進捗・着地予測 | ホーム / サマリー |
| 客単価 | 売上 ÷ 来店数 | 前期間・前年と比較 | サマリー / マイ成績 |
| 次回予約率 | 次回予約を取れた人数 ÷ 来店数（新規 = 初回来店、2回目以降 = 再来 のそれぞれ）。分母はSalonOneの来店数、分子は日報 | 70%以上=緑、50%以上=黄、50%未満=赤 | ホーム / 日報 / サマリー |
| 次回予約数 | 日報の次回予約（新規 + 2回目以降）の合計。スタッフ評価・月の目標に使う | 目標設定の「次回予約数（件）」と比べる | ホーム / マイ成績 / サマリー |
| 媒体別の次回予約 | 次回予約を、お客様が最初に来たきっかけ（SalonOneの流入元）ごとに集計。新規の次回予約率の分母はマーケ集計のその媒体の新規客の来店 | どの媒体のお客様が次につながるか | マーケ |
| 次回予約率（予約データ β） | 来店した日の終わりまでに、その顧客の「より後の予約」が入っていた割合（SalonOneの予約明細から自動） | 日報の値と大きく違えば登録方法を見直す | 日報 / マイ成績 / サマリー |
| キャンセル率 | （キャンセル＋無断）÷（来店＋キャンセル＋無断） | 15%以上で注意表示 | サマリー |
| 来店回数の分布 | 登録顧客がこれまでに来店した回数（1回だけ / 2回以上 / 3回以上の割合） | 1回だけの割合を下げる | 顧客分析 |
| 日報の入力率 | 日報を入力した人日 ÷（スタッフ数 × 経過日数） | 100%を目指す | ホーム |
| 着地予測 | 今月の実績 + 残り日数を曜日別の平均売上で見込んだ値（±12%のレンジ付き） | 目標との差を見て打ち手を決める | ホーム / サマリー |

> 「新規」は2種類あります。売上サマリの **新規来店（延べ）** と、マーケ集計の **新規客（初めて予約した人数・1人=1）**。定義が違うため一致しません。

## 4. ホームの「やること」に出るもの

| 表示 | 対象 | 条件 |
|---|---|---|
| 昨日の日報が未入力 | スタッフ / 店長以上 | 昨日SalonOneで来店を担当したのに日報が無い |
| 今日の日報 | スタッフ | 来店がある日の15時以降（18時以降は強調） |
| 昨日の出納帳が締められていない | 店長以上 | 出納帳を始めた店舗で、昨日に現金の動きがあるのに締めていない |
| 出納帳の未締め | 店長以上 | 昨日より前で、現金の動きがあるのに締めていない日 |
| 締めた後に金額が変わった日 | 店長以上 | 締めた後にSalonOneの現金売上、または前日までの記録（繰越）が変わった |
| 今月の現金過不足 | オーナー / マネージャー | 締めた日に過不足がある（合計と日数） |
| 昨日の入金突合が未入力・途中 | 店長以上 | 昨日の売上記録があるのに実際額が未入力（出納帳で締めた日は現金が自動で入る） |
| 昨日の入金に差異 | 店長以上 | 差額があるのにメモが無い |
| 今月の未突合 | 店長以上 | その月に突合を始めた日以降で、昨日より前の未入力日 |
| 翌月の希望休を申請 / 未申請 | スタッフ | 申請締切（設定・既定20日）までに未申請 |
| 翌月のシフトを分配・承認 | 店長以上 | 締切後に未承認のスタッフがいる（締切7日前から申請状況も表示） |
| 今月/翌月の目標が未設定 | 店長以上 | 店舗・スタッフの目標がどちらも無い（翌月分は月末5日間） |
| パスワード・サーバー保存の不足 | オーナー | `ADMIN_PASSWORD` 未設定、Supabase未設定・キー誤り |

「SalonOneで確認すること」には、担当者未設定の新規予約、流入元未設定の新規客、担当者なしの売上、支払い方法が未設定の会計、会計未処理の過去予約（予約データ β）が出ます。

## 5. 日報の次回予約（媒体別）

**SalonOneの分析APIには「次回予約数」の項目がありません。** そのため次回予約は日報で入力し、スタッフ評価・目標・媒体分析に使います（予約明細からの自動推定は次の「β」を参照。確認用の目安です）。

| 項目 | 入れ方 |
|---|---|
| 新規 | その日が初めての来店だったお客様のうち、次回の予約を取れた人数 |
| 2回目以降 | 2回目以上の来店だったお客様のうち、次回の予約を取れた人数 |
| 媒体 | お客様が**最初に来たきっかけ**（SalonOneの流入元）。選択肢はSalonOneの流入元から自動で作られ、今月よく使われている順に並ぶ。わからないときは「その他・不明」 |

- 合計（新規 / 2回目以降）は媒体別の入力から自動で計算され、SalonOneのその日の来店数（新規・2回目以降）が目安として並ぶ。来店数を超えると注意が出る
- 媒体別に入力する前の日報は内訳がないため、マーケの「媒体別の次回予約」では「媒体の内訳なし（以前の日報）」としてまとめて表示。日報を開くと合計が「その他・不明」に入った状態で表示され、媒体を入れ直して保存すると内訳つきになる
- 集計: マーケ →「媒体別の次回予約」（合計の多い順・新規の次回予約率つき）と「媒体別の新規獲得」表の次回予約の列。スタッフ別はサマリーの日報サマリとマーケの担当者別の表
- 保存形式: `vie:manual:<YYYY-MM>` の日報に `src`（`{"<流入元ID>"|"other": {"n": 新規, "r": 2回目以降}}`）。`nextNew` / `nextRepeat` はサーバーが `src` の合計から作る

## 6. 次回予約の自動推定（β）について

SalonOneの予約明細（`/appointments`）から、次の条件で数えます。

- **来店**: 会計済み（ステータスや会計日時から判定）の予約
- **次回予約あり**: 同じ顧客の「開始日時がより後」の予約が、来店日の終わり（日本時間）までに作成されていた
  - 後からキャンセルされた予約も、来店日の時点で入っていれば数える（取消日時が無い場合は数えない）
- **新規/2回目以降**: 予約の新規フラグ、無ければ顧客の初回来店日で判定

SalonOneの仕様書は明細の項目名・ステータス値を定めていないため、実データで判定できているかを
**設定タブ →「予約データ連携（β）」** で確認できます（取得件数・使った項目名・ステータスの内訳・推定値と日報の比較）。
「推定に使えます」と表示されない場合、推定値は画面に出ません（日報の手入力だけで運用できます）。

運用が安定し、日報の数字と推定値がほぼ一致するようになれば、次回予約の手入力は確認だけに減らせます。
ただし推定では**媒体（流入元）ごとの内訳**までは分からないため、媒体別の次回予約は日報の入力から集計します（日報の画面では推定値を確認用の目安として表示し、入力欄には自動で入れません）。

## 7. 出納帳（現金の管理）

**レジの現金を「帳簿上あるはずの額」と「実際に数えた額」で毎日突き合わせ、すべての操作をログに残す**ための画面です（店長以上。店舗ごと）。

**帳簿上の残高** = 前日からの繰越 ＋ 現金売上（SalonOneの現金払いの会計・自動） ＋ 入金（記録） − 出金（記録）

| 手順 | 内容 |
|---|---|
| はじめに | 開始日の開店前のレジの現金を「開始時の残高」に入力（釣り銭準備金を入れると締めのときに預け入れの目安が出る） |
| その都度 | 現金で払った経費、銀行への預け入れ、釣り銭の補充、回数券などSalonOneの日別売上に出ない現金の販売を記録（科目・摘要・支払先・**レジ／金庫のどちらから払ったか**・領収書の写真または紙の有無・担当者） |
| 金庫 | 金庫（レジとは別の予備現金）から払った経費は支払元を「金庫」にして記録。レジと金庫の出し入れは科目「レジから金庫へ移す」「金庫からレジへ補充」。金庫の残高は記録から自動計算され、「金庫を数えた額」を記録するとその額が以降の基準になる |
| 閉店後 | レジの現金を金種ごとに数えて「実査を保存」→ 帳簿との過不足を確認 → 締める（過不足があるときは理由が必須） |
| 翌日 | 締めた日の実査額がそのまま翌日の繰越になる（過不足はその日で確定） |

- **締めた日は修正できません**。直すときは理由を入れて「締めを取り消す」→ 修正 → 締め直し（取消の履歴はログに残る）
- 記録は削除できず、**取消（理由つき・取消線で残る）**のみ
- **締めた後に SalonOne の現金売上が変わった**（会計の修正・支払い方法の変更など）、または前日までの記録が変わって繰越がずれた場合は、出納帳とホームに警告が出ます
- 締めた日の「実際の現金売上」（実査 − 繰越 − 入金 ＋ 出金）は、入金突合の現金欄に自動で入ります
- **操作ログ**: 記録・修正（変更前→変更後）・取消・実査・締め・締めの取消・設定の変更を、日時・操作した人（オーナー/マネージャー/店長）・担当者（実際にレジを扱ったスタッフ）・理由とともに保存。ログは修正・削除できません
- **領収書の写真**: 記録のときに「写真を追加」でスマホのカメラ・写真から添付（1件5枚まで。端末側で縮小して Supabase Storage の非公開バケットに保存。閲覧は短時間の署名付きURL）。写真がないときは「紙で保管」のチェックだけでも記録できます
- **金庫**: 金庫からの支払い・金庫への入金はレジの帳簿残高・締めには影響しません。レジ⇔金庫の移動は両方の残高に反映されます。「金庫の現金（現在）」は直近の「数えた額」（なければ設定の開始時の金庫の現金）から記録を積み上げて計算します
- CSV: 月の出納帳（日付・区分・科目・摘要・レジ/金庫・入金・出金・レジ残高・記録者・担当者・領収書・状態）と操作ログを、会計ソフト・税理士への提出用に書き出せます
- 設定: 科目の名前変更・非表示・追加、現金とみなす支払い方法（既定は名前に「現金」を含むもの）はオーナー/マネージャー。開始日・開始残高の変更もオーナー/マネージャー（店長は最初の設定のみ）
- 回数券・サブスクの販売はSalonOneの日別の現金売上に含まれないことがあります。現金で受け取ったときは「回数券・サブスク等の販売（現金）」として入金を記録してください
