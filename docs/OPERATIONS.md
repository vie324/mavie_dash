# 業務分担ガイド（SalonOne × vie ダッシュボード）

**SalonOne は「記録する場所」、このダッシュボードは「見る・振り返る・決める場所」** です。
売上・来店・新規・入会などの数字はすべて SalonOne の入力から自動で作られます。
このツールで手入力するのは **SalonOne にない数字だけ**（日報・入金の実際額・目標など）です。

アプリ内でも「その他 → 使い方・業務分担」から同じ内容をスマホで確認できます。

---

## 1. どちらでやるか（業務の振り分け）

| 業務 | SalonOne | ダッシュボード | 補足 |
|---|:---:|:---:|---|
| 予約の登録・変更・キャンセル | ◎ | — | **担当スタッフを必ず設定**（スタッフ別の新規・入会・次回予約の集計に使う） |
| 会計（支払い方法の選択・物販の登録） | ◎ | — | 支払い方法の選び間違いは入金突合の差異になる |
| 次回予約の登録 | ◎ | 確認 | **会計時にSalonOneで予約を入れる**と、ダッシュボードが次回予約率を自動推定（β） |
| キャンセル・無断キャンセルの処理 | ◎ | 確認 | 処理漏れはホームの「SalonOneで確認すること」に「会計未処理の予約」として出る |
| 顧客の流入元・生年の登録 | ◎ | — | 媒体別の集客効果・年代分析に使う |
| 回数券・サブスクの契約 | ◎ | — | 入会数・継続率に使う |
| スタッフ・メニュー・店舗の登録 | ◎ | — | ダッシュボード側での登録は不要（自動で反映） |
| 予約台帳・カルテ・顧客対応 | ◎ | — | ダッシュボードは個人情報を表示しない設計 |
| 売上・来店・客単価・目標進捗の確認 | △ | ◎ | 着地予測・前期比・前年比・店舗/スタッフ比較 |
| 日報（次回予約 新規/既存・ブログ・SNS・★5口コミ） | — | ◎ | SalonOneに無い数字。退勤前に入力 |
| 入金突合（現金の実査・カード/QRの端末集計） | — | ◎ | SalonOneの支払い方法別の記録と照合 |
| シフト（希望休の申請 → 分配 → 承認） | — | ◎ | ルール・申請締切は設定タブで変更 |
| 目標・基本給の設定、インセンティブの確認 | — | ◎ | オーナー/マネージャー/店長 |
| 広告費（Meta/TikTok） | ◎ | 確認 | SalonOneの広告連携の値を自動取得 |
| 広告費（HPBなどAPIに無い媒体） | — | ◎ | 日報入力タブの広告費欄（オーナー/マネージャー） |

## 2. 役割別のルーティン

### スタッフ
| 頻度 | やること | 画面 |
|---|---|---|
| 毎日（退勤前） | 日報を入力（次回予約の新規/既存・ブログ・SNS・★5口コミ）。SalonOneの来店数が分母として表示され、予約データからの推定値も参考に出る | 日報 |
| 毎日 | ホームで今日の実績・今月の進捗・やることを確認 | ホーム |
| 毎週 | 次回予約率・客単価・店内順位を振り返る | マイ成績 |
| 毎月（締切日まで） | 翌月の希望休を申請 | シフト |

**見る数字**: 今月の売上と目標までの残り / 次回予約率（新規・既存） / 新規の入会数 / 店内順位・客単価

### 店長
| 頻度 | やること | 画面 |
|---|---|---|
| 毎日（閉店後） | 入金突合（現金を数えて入力・カード/QRは端末の日計） | 入金突合 |
| 毎日 | 日報の未入力者に声かけ（ホームに名前が出る） | ホーム |
| 毎日 | SalonOneの会計未処理・担当者未設定をなくす | ホーム →SalonOne |
| 毎週 | スタッフ別の次回予約率・客単価・キャンセル率、着地予測と目標の差 | サマリー |
| 月末 | 翌月の目標設定、今月の未突合ゼロ | 目標 / 入金突合 |
| 申請締切後 | シフトを自動分配 → 調整 → 承認 | シフト |

**見る数字**: 店舗の目標進捗・着地予測 / 日報の入力率 / 次回予約率 / 新規の入会率 / キャンセル率

### マネージャー
| 頻度 | やること | 画面 |
|---|---|---|
| 毎日 | 全店舗の未突合・日報未入力を確認 | ホーム |
| 毎週 | 店舗比較（達成率・客単価・新規・キャンセル率）、媒体別の新規獲得と入会率 | サマリー / マーケ |
| 毎月 | 店舗目標の設定、継続率・離反の確認 | 目標 / 顧客分析 |

### オーナー
| 頻度 | やること | 画面 |
|---|---|---|
| 毎日 | ホームの「やること」（未突合・設定の不足） | ホーム |
| 毎週 | 全店舗の着地予測と目標の差、SalonOneの入力漏れ | ホーム / サマリー |
| 月初 | インセンティブの確認（対象月を先月にする） | インセンティブ |
| 毎月 | 媒体別CPA・ROASと広告予算、スタッフアカウントの発行・パスワード管理 | マーケ / 設定 |

## 3. 見る数字の定義と目安

| 指標 | 定義 | 目安・表示 | どこで見る |
|---|---|---|---|
| 売上（会計済み） | 会計が完了した売上。日別・スタッフ別・支払い内訳と一致する基準（設定で粗売上/消化売上に切替可） | 目標に対する進捗・着地予測 | ホーム / サマリー |
| 客単価 | 売上 ÷ 来店数 | 前期間・前年と比較 | サマリー / マイ成績 |
| 次回予約率 | 次回予約を取れた人数 ÷ 来店数（新規・既存それぞれ）。分母はSalonOneの来店数、分子は日報 | 70%以上=緑、50%以上=黄、50%未満=赤 | ホーム / 日報 / サマリー |
| 次回予約率（予約データ β） | 来店した日の終わりまでに、その顧客の「より後の予約」が入っていた割合（SalonOneの予約明細から自動） | 日報の値と大きく違えば登録方法を見直す | 日報 / マイ成績 / サマリー |
| 新規の入会率 | 期間内に回数券・サブスクを契約した新規客 ÷ 新規予約数 | 媒体別・スタッフ別に比較 | マーケ |
| キャンセル率 | （キャンセル＋無断）÷（来店＋キャンセル＋無断） | 15%以上で注意表示 | サマリー |
| 継続率 | 期間内に入会した顧客のうち契約が有効な人の割合 | 媒体・担当者別に確認 | マーケ / 顧客分析 |
| 日報の入力率 | 日報を入力した人日 ÷（スタッフ数 × 経過日数） | 100%を目指す | ホーム |
| 着地予測 | 今月の実績 + 残り日数を曜日別の平均売上で見込んだ値（±12%のレンジ付き） | 目標との差を見て打ち手を決める | ホーム / サマリー |

> 「新規」は2種類あります。売上サマリの **新規来店（延べ）** と、マーケ集計の **新規客（初めて予約した人数・1人=1）**。定義が違うため一致しません。

## 4. ホームの「やること」に出るもの

| 表示 | 対象 | 条件 |
|---|---|---|
| 昨日の日報が未入力 | スタッフ / 店長以上 | 昨日SalonOneで来店を担当したのに日報が無い |
| 今日の日報 | スタッフ | 来店がある日の15時以降（18時以降は強調） |
| 昨日の入金突合が未入力・途中 | 店長以上 | 昨日の売上記録があるのに実際額が未入力 |
| 昨日の入金に差異 | 店長以上 | 差額があるのにメモが無い |
| 今月の未突合 | 店長以上 | その月に突合を始めた日以降で、昨日より前の未入力日 |
| 翌月の希望休を申請 / 未申請 | スタッフ | 申請締切（設定・既定20日）までに未申請 |
| 翌月のシフトを分配・承認 | 店長以上 | 締切後に未承認のスタッフがいる（締切7日前から申請状況も表示） |
| 今月/翌月の目標が未設定 | 店長以上 | 店舗・スタッフの目標がどちらも無い（翌月分は月末5日間） |
| パスワード・サーバー保存の不足 | オーナー | `ADMIN_PASSWORD` 未設定、Supabase未設定・キー誤り |

「SalonOneで確認すること」には、担当者未設定の新規予約、流入元未設定の新規客、担当者なしの売上、支払い方法が未設定の会計、会計未処理の過去予約（予約データ β）が出ます。

---

## 5. 次回予約の自動推定（β）について

SalonOneの予約明細（`/appointments`）から、次の条件で数えます。

- **来店**: 会計済み（ステータスや会計日時から判定）の予約
- **次回予約あり**: 同じ顧客の「開始日時がより後」の予約が、来店日の終わり（日本時間）までに作成されていた
  - 後からキャンセルされた予約も、来店日の時点で入っていれば数える（取消日時が無い場合は数えない）
- **新規/既存**: 予約の新規フラグ、無ければ顧客の初回来店日で判定

SalonOneの仕様書は明細の項目名・ステータス値を定めていないため、実データで判定できているかを
**設定タブ →「予約データ連携（β）」** で確認できます（取得件数・使った項目名・ステータスの内訳・推定値と日報の比較）。
「推定に使えます」と表示されない場合、推定値は画面に出ません（日報の手入力だけで運用できます）。

運用が安定し、日報の数字と推定値がほぼ一致するようになれば、次回予約の手入力は確認だけに減らせます。
